Throwaway prototype — issue #43

Per-Program navigation restructuring

This prototypes the state model behind the new per-Program nav from issue #43: a sidebar of Finished + the Module list, a Module's tabbed Lessons/Assignments, a due-soon Landing aggregate, and a Finished view that Done things can be un-marked from. The visual language (dark Gruvbox tokens, reading-list layout) is already settled — this is not a look-and-feel exploration. The question is: does "Done" hiding things from normal browsing, cascading down when a whole Module is marked Done, actually hold together once you push it through edge cases? Two rules are baked in on purpose so you can feel whether they're right:

  • Marking a Module Done cascades down: all its Lessons/Assignments become Done too, and it (and them) disappear from normal browsing into Finished.
  • Marking a Lesson/Assignment Done individually does not touch its parent Module's Done flag — a Module can sit in the sidebar with some of its contents already finished.
  • Un-marking a Lesson/Assignment whose Module is Done pulls that Module back out of Done too (so the item is reachable again) — but touches nothing else in it: every other already-Done Lesson/Assignment in that Module stays Done.
